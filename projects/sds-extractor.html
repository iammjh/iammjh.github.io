01 / THE PROBLEM

The same information, in different layouts.

A corporate textile client needed product names, chemical names, and CAS numbers from SDS PDFs in spreadsheet form. The challenge is that the information can sit in tables, wrap across lines, or appear under different labels.

My contribution

I built the extraction tool for this client workflow, combining a Python parser with browser uploads and Excel export. The same extraction logic also supports individual files and folders from the command line.

02 / THE APPROACH

Follow the document’s structure.

The parser reads product identifiers from Section 1 and locates the composition information in Section 3. It tries table extraction first, then falls back to text when tables yield no items. The extracted records become a three-column workbook.

03 / KEY DECISIONS

The details that shape the build.

01

Use structure before pattern matching

Section boundaries narrow the composition search. Product-name patterns handle different labels, while nearby text helps recover chemical names that wrap around CAS numbers.

02

Make incomplete results visible

Files with no extracted ingredients produce an N/A row. A failed file produces an error row while the batch continues, giving the reviewer a place to investigate.

03

Deliver something usable in Excel

pandas and openpyxl create the workbook with headers, adjusted column widths, and row heights. The result is ready for review in the client’s existing spreadsheet workflow.

04 / THE RESULT

A repeatable route from PDF to spreadsheet.

The tool accepts multiple PDFs and exports product, chemical, and CAS fields together. It puts extraction and formatting into one workflow, with the original documents available for checking the results.

A constraint worth understanding

Extraction depends on readable PDF text and recognizable layouts. The current pipeline has no OCR stage; scanned documents and unusual formatting need separate handling or manual review.
